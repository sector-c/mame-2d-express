# MAME 2D Express

A local-only, game-first arcade graphics extraction prototype. Select a game, supply your own legally obtained ROM ZIP, check its contents against MAME's ROM hashes, and create a graphics atlas using a supported decoder or a clearly labeled experimental mode.

**Current status: early prototype. Not a universal sprite ripper or a producer of finished Spriters Resource sheets.** Accurate RGB palettes, composed character animation frames, complete backgrounds and unused-asset tracing still need specialized work.

## Install

Requires Python 3.10+ and Pillow; Tkinter is included with many desktop Python installations (some Linux distributions require the `python3-tk` OS package).

```sh
python -m pip install -r requirements.txt
python app.py
```

All work, database files, ROM inspection, and graphics output remain **on your computer**. No ROMs are downloaded or uploaded.

## First launch

1. Choose **Import from installed MAME** and browse to your `mame`/`mame.exe` executable. Or use **Import MAME XML** with an XML file generated by `mame -listxml > mame.xml`.
2. Search the imported game database and **select a game**.
3. Choose its **ROM ZIP**. Add parent/BIOS ZIPs if needed for a split ROM set.
4. Click **Verify hashes**. The tool calculates local ROM SHA-1, CRC32 and file sizes and checks the imported MAME expectations. A complete match means the ZIP contents match the catalog; it does not guarantee all gameplay dependencies (e.g. CHDs) are present.
5. For **1942** and **Commando** (the original MAME shortnames only), choose **Decode known layout**. Other games can use **Experimental scan (untested)**. Experimental results are guesses, not authentic decoded graphics.

A local SQLite catalog is generated at `~/.mame_2d_express/catalog.sqlite3`, containing game metadata, expected component hashes, and independent support/review fields. No ROM image data is stored in the DB. MAME installation/XML provides authoritative metadata; the repo does not ship ROM hashes for the entire catalog.

## CLI

```sh
python app.py import-xml mame.xml
python app.py import-mame /path/to/mame
python app.py games --search commando
python app.py verify 1942 /path/to/1942.zip
python app.py verify 1942 /path/to/1942.zip --extra /path/to/parent.zip
python app.py extract 1942 /path/to/1942.zip --output ./output
python app.py experimental puckman /path/to/puckman.zip --output ./output
```

The known-layout exports preserve original **8×8 and 16×16 tile dimensions** but use **grayscale placeholder palettes**, not the final RGB colors. They are not assembled character frames. The experimental exporter guesses a contiguous 4bpp pixel layout on up to 24 archive members, so it may output nonsense. Every output includes a JSON manifest with provenance and a non-submission-ready warning.

The direct ROM region assembly currently handles simple contiguous `ROM_LOAD` ranges only. MAME entries using interleaving/continue/reload need a separate hardware-specific loader or MAME region bridge; the application refuses to silently guess.

## Project plan

- **M1:** game-first UI, hash catalog, ZIP validation, honest extraction statuses (prototype)
- **M2:** authentic palette/PROM reconstruction and tested reference PNGs for early Capcom
- **M3:** sprite attribute decoding, multi-tile assembly, foreground/background composition, animation capture
- **M4:** MAME Lua tracing, observed vs unobserved asset reports, review workflow
- **M5:** additional hardware families based on verified community contributions

Graphics layouts are based on MAME's [1942 driver](https://github.com/mamedev/mame/blob/master/src/mame/capcom/1942.cpp) and [Commando driver](https://github.com/mamedev/mame/blob/master/src/mame/capcom/commando.cpp). MAME's [`-listxml` documentation](https://docs.mamedev.org/commandline/commandline-all.html) describes its catalog data.
